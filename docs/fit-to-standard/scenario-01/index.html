全要件 判定一覧（20件）
No.要件判定IFS 標準機能 / 推奨アクション
1購買発注の登録・リリース・確認
仕入先・品目・数量・納期を入力して購買発注を作成し、リリース→確認まで標準フローで処理する。		FitPurchase Order 標準機能（PurchaseOrderHandling）で全フロー対応。設定・開発不要。
2発注残の一覧表示・Excel出力
発注済みで未着荷の明細を一覧化し、仕入先・残数・予定納期をExcelにエクスポートして日次業務で活用する。		Fitクイックレポート（発注残ビュー）で実現。SQL設定のみ、開発不要で即日稼働。
3入荷時の品質検品・合否判定記録
入荷ごとに品質検査結果（合格/不合格/条件付き）を記録し、不合格品は自動的に返品処理フローへ誘導する。		FitReceipt Inspection 標準機能で検品・判定・返品フローまで一括対応。追加開発不要。
4発注・入荷・請求書の3方向照合
購買発注・入荷実績・仕入先請求書の金額・数量を突合し、差異がある場合は照合保留として担当者に通知する。		FitSupplier Invoice Matching 標準機能で3方向照合・差異通知まで対応。
5発注金額に応じた多段階承認フロー
50万円未満は部長承認1段階、50万円以上は部長→役員の2段階承認。承認者不在時は代理者へ自動転送する。		Config承認グループ・承認テンプレート設定で金額別多段階承認を実現。代理者設定も標準対応。
6仕入先のKPI・納期遵守率レポート
仕入先ごとに納期遵守率・品質不良率・発注金額を集計し、月次評価レポートとして出力する。		FitSupplier Performance Management 標準レポートで KPI 集計・出力まで対応。
7発注明細ごとの部門別コスト配賦入力
1発注に複数部門のコストセンターを明細単位で指定し、会計連携で部門別原価管理レポートに反映させる。		Configコストセンター設定 + C_COST_CENTER 拡張フィールドを明細に追加することで実現。
8仕入先別SLA超過時のアラートメール
仕入先ごとに定めたリードタイム（SLA）を超えた発注が存在する場合、担当者に自動メールを送信する。		Dev標準にSLA管理機能なし。C_SLA_DAYS 拡張フィールド追加 + IFS Event によるアラート実装が必要。
9購買発注書PDFの自動生成・メール送信
発注リリース時に発注書PDFを自動生成し、仕入先のメールアドレスに自動送信する。		FitDocument Management + Report Designer 標準機能でPDF自動生成・メール送信まで対応。
10購買カタログ品の発注依頼・承認フロー
社内ユーザーがカタログから品目を選んで発注依頼を起票し、購買担当者が承認後に発注に変換する。		FitPurchase Requisition + Supplier Catalog 標準機能で依頼→承認→発注変換まで一貫対応。
11複数仕入先への同時見積依頼（RFQ）
同一品目・仕様を複数の仕入先に一括で見積依頼し、回答を比較して最適仕入先を選定・発注する。		FitRequest for Quotation 標準機能で一括送付・比較・発注変換まで対応。
12プロジェクトコード別の原価管理
発注ヘッダーにプロジェクトコードを紐付け、プロジェクト別の購買コストを会計システムへ自動連携する。		ConfigProject Accounting 設定 + C_PROJECT_CODE 拡張フィールドを発注ヘッダーに追加することで実現。
13購買発注の承認履歴の監査証跡保管
誰がいつ何の発注を承認したかをすべて記録し、内部監査・コンプライアンス対応のために検索・出力できる。		Dev標準承認履歴は保持期間・項目が限定的。C_PO_APPROVAL_LOG_TAB カスタムエンティティの実装が必要。
14受注・製造オーダへの在庫引当・予約
発注品目が入庫された際に、特定の受注や製造オーダに対して在庫を自動引当・予約する。		FitInventory Reservation 標準機能で引当・予約・解放まで対応。
15品目のロット・シリアル番号管理
入荷時にロット番号またはシリアル番号を付与し、払出・在庫移動・品質追跡をロット/シリアル単位で行う。		FitLot/Serial Tracking 標準機能で入荷登録から追跡まで対応。追加開発不要。
16外貨建て発注と自動為替換算
USD・EUR等の外貨で発注を作成し、入力日の為替レートで自動換算して会計仕訳を生成する。		FitMulti-Currency 標準機能で外貨発注・為替換算・会計仕訳生成まで一貫対応。
17仕入先ごとの優先配送業者設定
仕入先マスタに優先配送業者を設定し、発注書作成時に自動的に配送業者情報を引き継ぐ。		Dev標準に配送業者マスタ連携機能なし。C_PREFERRED_CARRIER 拡張フィールド追加と入力画面カスタマイズが必要。
18発注金額上限超過時の自動警告
承認グループに設定された金額上限を超える発注が登録された場合、承認者に警告を表示して上位承認者へ転送する。		Config承認グループの金額上限設定（Maximum Amount）で自動警告・上位転送を実現。設定のみ。
19自社独自の支払条件コード体系の管理
標準の支払条件コードとは別に、自社独自の支払条件コード体系を持ち、仕入先別に設定・管理する。		Dev標準支払条件では自社コード体系に対応不可。C_PAYMENT_TERMS 拡張コードテーブルの実装が必要。
20期末棚卸（物理インベントリカウント）
年次・期次の棚卸で全品目の現物数を記録し、システム在庫との差異を自動計算して差異仕訳を生成する。		FitPhysical Inventory 標準機能で棚卸リスト作成・差異計算・仕訳生成まで対応。
⚠️ 本レポートについて

本判定はAIによる自動分析の結果であり、架空のプロジェクト要件に基づくサンプルです。実在するプロジェクト・顧客とは無関係です。また、実際のプロジェクトにおいてはAIの判定をそのまま採用するのではなく、IFSに精通した人間のレビュアーが業務要件・カスタマイズ方針・運用制約を踏まえて最終判断を行うことが不可欠です。
