Fit to Standard 詳細 — No.15 / 在庫管理

ロット・シリアル番号管理

判定: Fit ✓ — IFS Cloud 標準機能で完全対応

⚠️ 本判定は架空プロジェクトのサンプルです。実際のプロジェクトでは IFS に精通した人間のレビュアーが最終判断を行うことが不可欠です。
ロット・シリアル管理とは

製造業・医療・食品などの業界では、品目を「ロット（同一製造条件でまとめた単位）」または「シリアル番号（個体識別番号）」で管理することが品質管理・トレーサビリティの観点で不可欠です。IFS Cloud はこの機能を標準で備えており、追加開発なしで実現できます。

IFS Cloud での標準フロー
1

品目マスタでの追跡種別設定

品目マスタの「Lot Tracking」フィールドで Order Based（発注単位） または Lot Tracking（ロット番号付与） を選択。シリアル管理は「Serial Tracking」で設定。一度設定すれば以降の入荷・払出に自動適用されます。

2

入荷時のロット/シリアル番号登録

購買発注の入荷処理（Receive Parts）を行う際、ロット追跡品目はロット番号の入力が必須（入力なしはシステムがエラーで阻止）。バーコードスキャナやハンディターミナルにも対応。

3

在庫移動・払出でのロット追跡

倉庫間移動・製造払出・出荷のすべてでロット/シリアル番号が引き継がれます。「どのロットがどこにあるか」を IFS Cloud が常に管理します。

4

不良ロットの影響範囲追跡

問題のあるロット番号を指定するだけで、そのロットが使われた製造オーダ・出荷先・在庫場所を一覧表示。リコール・隔離対応も迅速に行えます。

ロット追跡 vs シリアル追跡
ロット/バッチ追跡

Lot/Batch Tracking

同一ロットを複数個まとめて1つのロット番号で管理。食品・医薬品・化学品など「製造バッチ単位」で品質管理が必要な品目に適します。

シリアル追跡

Serial Tracking

品目を1個ずつユニークなシリアル番号で管理。機械部品・電子機器など個体識別が必要な品目に適します。As-Built構造（製造完了時の構成）も記録可能。

Fit 判定の根拠
確認項目IFS Cloud の標準対応
標準プロセスの存在 「7.9.6.2 Handle Shop Order Batch and Serial Tracking」など、ロット/シリアル追跡を扱う公式プロセスモデルが IFS Cloud 25R2 に複数収録されている
入荷時の強制バリデーション ロット追跡品目でロット番号を入力しない場合、システムが自動でエラーを発生させ入庫をブロック（INVENT モジュールの標準制御）
追跡種別の管理 INVENT_PART_LOT_MANAGER_API が ORDER_BASED / LOT_TRACKING / SERIAL_TRACKING の種別管理・変更バリデーションを標準実装済み
品質管理との連携 品質検査（QUAMAN）モジュールとの連携も標準対応。ロット追跡品目の検査には有効なロット番号が必須
購買モジュールとの連携 購買方法によってシリアル/ロット追跡が必須化される仕組みも PURCH モジュールに標準実装済み
ソースコードレベルの分析（抜粋）

標準プロセス「7.9.6.2 Handle Shop Order Batch and Serial Tracking」に関連する PL/SQL パッケージを特定し、実装レベルで解析した結果です。

① INVENT_PART_LOT_MANAGER_API — ロット追跡種別の変更バリデーション（Core / INVENT モジュール）
-- ロット追跡種別変更時の整合性チェック PROCEDURE Check_Lot_Track_Change ( part_no_ IN VARCHAR2, lot_tracking_code_db_ IN VARCHAR2, -- ORDER_BASED / LOT_TRACKING serial_tracking_code_db_ IN VARCHAR2 ) IS BEGIN -- 在庫内の現状ロット状態を取得 lot_state_ := Invent_Part_Quantity_Util_API.Get_Lot_Batch_Track_Status(part_no_); -- ORDER_BASED → LOT_TRACKING への変更のみ許容（在庫整合性保護） IF NOT ((lot_tracking_code_db_ = DB_ORDER_BASED) AND (lot_state_ = DB_LOT_TRACKING)) THEN Error_SYS.Record_General('NOLOTTRACKING: The part exists in inventory with :P1', Part_Lot_Tracking_API.Decode(lot_state_)); END IF; -- 全サイトで負在庫・評価方法との整合性もチェック FOR part_rec IN get_rec LOOP Inventory_Part_API.Check_Value_Method_Combination(...); Inventory_Part_API.Check_Negative_On_Hand(...); END LOOP; END Check_Lot_Track_Change;
② INVENTORY_PART_IN_STOCK_API / INVENT_PART_LOT_MANAGER_API — 入荷・在庫移動時のロット必須チェック（INVENT モジュール）

標準プロセスの受入処理（Receive Parts）に対応するパッケージを解析したところ、ロット追跡品目の入庫・在庫変動操作において複数箇所でロット番号の存在チェックが実装されていることを確認しました。

-- INVENTORY_PART_IN_STOCK_API（在庫移動・入庫の中核API） -- InventoryPartInStock.plsql 内のバリデーション群（抜粋） IF (lot_tracking_code_ != Part_Lot_Tracking_API.DB_NOT_LOT_TRACKING) THEN IF (lot_batch_no_ = '*') THEN -- ロット追跡品でワイルドカード '*' は許容しない Error_SYS.Record_General(lu_name_, 'LOTTRACKEDMUSTNOTBESTAR: This Part is using Lot Tracking so Lot Batch No cannot be :P1.', lot_batch_no_); END IF; ELSIF (lot_batch_no_ != '*') THEN -- 非ロット追跡品に具体的なロット番号を与えることも禁止 Error_SYS.Record_General(lu_name_, 'NOTLOTTRACKEDMUSTBESTAR: This Part is not using Lot Tracking so Lot Batch No must be :P1.', '*'); END IF; -- シリアル追跡品目にも同様のチェックが対になって実装 IF (serial_tracking_code_ != DB_NOT_SERIAL_TRACKING) THEN Check_Serial_No_Required_(serial_no_, part_no_, contract_); END IF;
③ 品質管理・購買モジュールとの連携 — 横断的な標準実装の確認

プロセスに関連する QUAMAN（品質管理）・PURCH（購買）モジュールのパッケージも解析し、ロット追跡がモジュールをまたいで一貫して強制されることを確認しました。

-- QUAMAN / Analysis.plsql — 品質検査にもロット番号必須チェック IF (Inventory_Part_API.Get_Lot_Tracking_Code(part_no_) != Part_Lot_Tracking_API.DB_NOT_LOT_TRACKING) THEN IF (lot_batch_no_ IS NULL OR lot_batch_no_ = '*') THEN Error_SYS.Record_General(lu_name_, 'LOTNONOTNULL: Part No :P1 is a Lot Track Part. Lot Batch no must have a valid batch no.', part_no_); END IF; END IF; -- PURCH / MtrlPurchaseTaskUtil.plsql — 購買方法によるロット/シリアル強制 IF (purchase_type_ = 'SERIAL_TRACKED') AND (Inventory_Part_API.Get_Serial_Tracking_Code(part_no_) = Part_Serial_Tracking_API.DB_NOT_SERIAL_TRACKING) THEN Error_SYS.Record_General(lu_name_, 'SERTRKERR: Part must be a serial tracking or lot tracking part for purchase method :P1', purchase_type_); END IF;

以上の解析から、ロット/シリアル追跡は INVENT（在庫）・PURCH（購買）・QUAMAN（品質） の各モジュールで独立したバリデーションとして実装されており、どの経路で在庫操作を行ってもロット番号の整合性がシステム側で保証される設計になっていることが確認できます。

✓ 結論: Fit — 開発不要

品目マスタの追跡種別設定のみで、入荷・払出・在庫移動・品質検査・不良ロット追跡のすべてが IFS Cloud 標準機能で実現できます。カスタム開発は不要です。
