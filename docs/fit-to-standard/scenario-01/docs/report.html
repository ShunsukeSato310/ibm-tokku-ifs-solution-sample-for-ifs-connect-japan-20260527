Fit to Standard 分析レポート

調達領域 Fit to Standard 分析レポート

バージョン 1.0　／　2026-05-26　／　IFS Cloud 25R2 ／ 対象: 調達・購買 20要件

1. エグゼクティブサマリー
総要件数20件
Fit（標準対応）11件（55%）— 開発不要。標準機能をそのまま活用
Config（設定対応）5件（25%）— 設定作業のみで対応可能。拡張フィールド追加を含む
Dev（開発必要）4件（20%）— カスタム実装が必要。優先度付けを推奨
推定開発削減効果標準活用により開発工数を約80%削減可能と推定
2. Dev 要件 — 優先度と推奨アクション
No.要件優先度推奨アクション推定工数
8仕入先ごとのSLAアラート 高 仕入先拡張フィールド(SLA_DAYS)追加 + IFS Event でアラート実装 3〜5日
13承認履歴の監査証跡 高 カスタムエンティティ PO_APPROVAL_LOG 作成 + 承認イベントにフック 5〜7日
17優先配送業者の仕入先別設定 中 仕入先拡張フィールド(PREFERRED_CARRIER)追加 + 入力画面カスタマイズ 2〜3日
19カスタム支払条件コードの管理 低 拡張コードテーブル作成。標準支払条件との併用方式を検討 3〜5日
3. 推奨アクション（次のステップ）

フェーズ 1（即時対応）— Fit 要件の標準設定

  • 11件のFit要件を標準設定で有効化（担当: コンサルタント、期間: 2週間）
  • Purchase Order / RFQ / Supplier Performance の初期設定を実施

フェーズ 2（1ヶ月以内）— Config 要件の設定作業

  • 承認グループ設定（2段階承認フロー）を構築
  • コストセンター・プロジェクトコード拡張フィールドを追加
  • 発注金額上限設定を承認グループに反映

フェーズ 3（優先度順に開発）— Dev 要件

  • SLAアラート（優先度高）→ 承認履歴監査証跡（優先度高）の順で開発着手
  • 優先配送業者・カスタム支払条件は予算・スケジュールと照らして判断
