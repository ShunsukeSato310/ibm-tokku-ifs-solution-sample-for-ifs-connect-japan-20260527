発注残確認レポート
詳細設計書

バージョン 1.0　／　作成日: 2026-05-26　／　IFS Cloud 25R2

1. 使用ビュー定義
PURCHASE_ORDER
ORDER_NO（購買オーダ番号 / PK）、VENDOR_NO（仕入先ID）、STATE（ヘッダーステータス）
PURCHASE_ORDER_LINE
ORDER_NO（購買オーダ番号 / FK）、LINE_NO（明細番号）、RELEASE_NO（連番）、PART_NO（品目番号）、DESCRIPTION（品目名称）、BUY_QTY_DUE（発注数量）、PLANNED_RECEIPT_DATE（入庫予定日）、OBJSTATE（明細ステータス）
SUPPLIER_INFO
SUPPLIER_ID（仕入先ID / PK）、NAME（仕入先名）
2. SQL 設計

2.1 実装 SQL（IFS Cloud 実機検証済み）

SELECT l.ORDER_NO AS "購買オーダ番号", l.LINE_NO AS "明細番号", l.PART_NO AS "品目番号", l.DESCRIPTION AS "品目名称", h.VENDOR_NO AS "仕入先ID", s.NAME AS "仕入先名", l.BUY_QTY_DUE AS "発注数量", 0 AS "入荷済数量", l.BUY_QTY_DUE AS "発注残数量", TO_CHAR(l.PLANNED_RECEIPT_DATE, 'YYYY-MM-DD') AS "入庫予定日", CASE WHEN l.PLANNED_RECEIPT_DATE < SYSDATE THEN '遅延' ELSE '正常' END AS "遅延フラグ" FROM PURCHASE_ORDER h, PURCHASE_ORDER_LINE l, SUPPLIER_INFO s WHERE h.ORDER_NO = l.ORDER_NO AND s.SUPPLIER_ID = h.VENDOR_NO AND l.OBJSTATE = 'Released' ORDER BY l.PLANNED_RECEIPT_DATE

2.2 SQL 設計ポイント

項目設計判断と根拠
結合方式カンマ結合（ANSI JOIN ではなく FROM 句列挙）— IFS Cloud クイックレポートで動作確認済みのシンプルな内部結合を採用
OBJSTATE フィルタl.OBJSTATE = 'Released' で発注済み明細のみ抽出。'Closed'（完了）・'Cancelled'（キャンセル）を除外
入荷済数量PURCHASE_RECEIPT（入庫トランザクション）は本環境でデータが未登録のため 0 固定。実運用では SUM(r.QTY_INVOICED) のサブクエリへ変更可能
日付フォーマットTO_CHAR(..., 'YYYY-MM-DD') で文字列化。クイックレポートの DATE 型は環境ロケールで表示が変わるため明示的にフォーマット
遅延フラグCASE 式で SYSDATE（実行時刻）と比較。実行するたびに最新の遅延状況を反映
ソート入庫予定日昇順で最も緊急な発注残が先頭に表示される
