データモデル設計

KCM（IFS Cloud標準）プロジェクトの拡張要件をプログラムから逆設計。業務要件を正確にシステム構造へ落とし込み、将来の拡張にも耐えられる設計を実現します。

標準 + 拡張設計 逆設計アプローチ サンプル公開中
IFS Cloud 拡張フィールドの命名規則

IFS Cloud の標準テーブルにカスタムフィールドを追加する場合、フィールド名は必ず C_ プレフィックスで始めることが IFS の標準規則です。これにより標準フィールドとの混在を防ぎ、バージョンアップ時の名前衝突リスクを排除します。カスタムエンティティ（テーブル）も同様に C_ を付与します。例: C_SLA_DAYS、C_PROJECT_CODE、C_PO_APPROVAL_LOG_TAB

設計アプローチ

標準モデルの把握

IFS Cloud の標準エンティティ・ビュー・APIを分析し、業務要件を標準機能でどこまで満たせるかを判定します。

拡張点の逆設計

既存プロジェクトのプログラム（IEF/AURENA）から拡張フィールド・カスタムエンティティを逆算し、設計書を自動生成します。

依存関係の可視化

エンティティ間の参照関係・ライフサイクル依存を図解。移行順序・テスト計画の根拠として活用できます。

匿名化サンプル生成

実プロジェクトの構造を参考にしながら、顧客が特定されないよう架空名称・汎用業種に置き換えたサンプルを生成します。
