調達領域 拡張フィールド設計書

バージョン 1.0　／　2026-05-26　／　IFS Cloud 25R2　／　命名規則: C_ プレフィックス

1. 命名規則

C_ プレフィックスルール

IFS Cloud の標準拡張命名規則に従い、カスタムフィールドはすべて C_ で始める。これにより標準フィールドとの混在を防ぎ、バージョンアップ時の衝突リスクを排除する。カスタムテーブルも同様に C_ を付与する。

2. DDL — 標準テーブルへの拡張フィールド追加

SUPPLIER_INFO_TAB

-- C_ プレフィックスで標準テーブルに拡張フィールドを追加 ALTER TABLE supplier_info_tab ADD c_preferred_carrier VARCHAR2(30), ADD c_sla_days NUMBER(3), ADD c_payment_terms VARCHAR2(20); COMMENT ON COLUMN supplier_info_tab.c_preferred_carrier IS '[Custom] 優先配送業者コード'; COMMENT ON COLUMN supplier_info_tab.c_sla_days IS '[Custom] 標準納期SLA（日数）'; COMMENT ON COLUMN supplier_info_tab.c_payment_terms IS '[Custom] カスタム支払条件コード';

PURCHASE_ORDER_TAB

ALTER TABLE purchase_order_tab ADD c_project_code VARCHAR2(20), ADD c_approval_level NUMBER(1) DEFAULT 1 NOT NULL; COMMENT ON COLUMN purchase_order_tab.c_project_code IS '[Custom] 原価管理プロジェクトコード'; COMMENT ON COLUMN purchase_order_tab.c_approval_level IS '[Custom] 必要承認レベル(1=部長/2=役員)';

C_PO_APPROVAL_LOG_TAB（カスタムテーブル新規作成）

CREATE TABLE c_po_approval_log_tab ( c_log_id VARCHAR2(36) NOT NULL, -- UUID order_no VARCHAR2(12) NOT NULL, approver_id VARCHAR2(20) NOT NULL, approved_at TIMESTAMP NOT NULL, c_approval_level NUMBER(1) NOT NULL, c_comment_text VARCHAR2(200), rowversion DATE NOT NULL, CONSTRAINT c_po_approval_log_pk PRIMARY KEY (c_log_id), CONSTRAINT c_po_approval_log_fk FOREIGN KEY (order_no) REFERENCES purchase_order_tab(order_no) );
