調達領域 拡張フィールド設計書

バージョン 1.0　／　2026-05-26　／　IFS Cloud 25R2

1. 設計方針
設計アプローチIFS Cloud 標準テーブルへのフィールド追加（IEF拡張）+ カスタムエンティティ
命名規則拡張フィールドはすべて大文字スネークケース。標準フィールドと衝突しない名称
NULL許容方針業務上必須の項目のみ NOT NULL。移行時の後付けを考慮し基本は NULL 許容
バージョンアップ方針標準フィールドとの衝突チェックをリリース前に実施。AI が自動検出
2. 拡張 DDL（抜粋）

SUPPLIER_INFO_TAB への拡張

-- 優先配送業者・SLA・支払条件 拡張フィールド追加 ALTER TABLE supplier_info_tab ADD preferred_carrier VARCHAR2(30), ADD sla_days NUMBER(3), ADD payment_terms_custom VARCHAR2(20); COMMENT ON COLUMN supplier_info_tab.preferred_carrier IS '優先配送業者コード'; COMMENT ON COLUMN supplier_info_tab.sla_days IS '標準納期SLA（日数）'; COMMENT ON COLUMN supplier_info_tab.payment_terms_custom IS 'カスタム支払条件コード';

PO_APPROVAL_LOG_TAB カスタムエンティティ

CREATE TABLE po_approval_log_tab ( log_id VARCHAR2(36) NOT NULL, -- UUID order_no VARCHAR2(12) NOT NULL, -- FK: purchase_order_tab approver_id VARCHAR2(20) NOT NULL, approved_at TIMESTAMP NOT NULL, approval_level NUMBER(1) NOT NULL, comment_text VARCHAR2(200), rowversion DATE NOT NULL, CONSTRAINT po_approval_log_pk PRIMARY KEY (log_id), CONSTRAINT po_approval_log_fk FOREIGN KEY (order_no) REFERENCES purchase_order_tab(order_no) );
3. 移行ジョブとの連携
拡張フィールド移行ジョブ名移行元変換ロジック
PREFERRED_CARRIERSUPPLIER_UPDATE_CARRIER旧システム 配送マスタ配送業者コード変換テーブルで変換
SLA_DAYSSUPPLIER_UPDATE_SLA旧システム 取引先マスタリードタイム日数をそのまま移行
PROJECT_CODEPO_UPDATE_PROJECT旧システム 発注ヘッダプロジェクトコード変換テーブルで変換
PO_APPROVAL_LOGPO_APPROVAL_INSERT旧システム 承認履歴承認者ID・日時・レベルをマッピング
