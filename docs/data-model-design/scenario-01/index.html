調達拡張モデル設計
標準エンティティへの拡張フィールド設計サンプル

IFS Cloud 標準の調達エンティティに対して、KCM標準拡張パターンを逆設計したサンプルです。

標準 + 拡張 ER図 フィールド定義書 移行設計への連携
背景
従来の課題
  • 拡張フィールドがどこに定義されているか把握に時間がかかる
  • バージョンアップ時に拡張との衝突が発生しやすい
  • 設計書がなく口頭ノウハウに依存していた
AI逆設計で解決
  • プログラムから拡張フィールドを自動抽出・ドキュメント化
  • 標準との差分を明確化しバージョンアップ影響を早期特定
  • ER図・フィールド定義書を自動生成
ER 図（詳細）
調達領域 拡張エンティティ関連図
SUPPLIER_INFO_TAB (標準)
PK: SUPPLIER_NO (VARCHAR)
NAME (VARCHAR 100)
CATEGORY (VARCHAR 20)
DEFAULT_LANGUAGE (VARCHAR 5)
+ PREFERRED_CARRIER (VARCHAR 30) ★拡張
+ SLA_DAYS (NUMBER) ★拡張
+ PAYMENT_TERMS_CUSTOM (VARCHAR 20) ★拡張
PURCHASE_ORDER_TAB (標準)
PK: ORDER_NO (VARCHAR 12)
FK: SUPPLIER_NO
WANTED_DELIVERY_DATE (DATE)
AUTHORIZE_CODE (VARCHAR 20)
OBJSTATE (VARCHAR 20)
+ PROJECT_CODE (VARCHAR 20) ★拡張
+ APPROVAL_LEVEL (NUMBER) ★拡張
PO_APPROVAL_LOG_TAB (拡張)
PK: LOG_ID (VARCHAR UUID)
FK: ORDER_NO
APPROVER_ID (VARCHAR 20)
APPROVED_AT (TIMESTAMP)
APPROVAL_LEVEL (NUMBER)
COMMENT_TEXT (VARCHAR 200)
PURCHASE_ORDER_LINE_TAB (標準)
PK: ORDER_NO + LINE_NO
FK: ORDER_NO
PART_NO (VARCHAR 25)
BUY_QTY_DUE (NUMBER)
+ COST_CENTER (VARCHAR 20) ★拡張
+ INTERNAL_ORDER_NO (VARCHAR 20) ★拡張
