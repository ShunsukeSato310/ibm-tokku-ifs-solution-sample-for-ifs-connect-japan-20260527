調達拡張モデル設計
C_ プレフィックスによる IFS 標準拡張

IFS Cloud の標準命名規則に従い、カスタムフィールドは C_ プレフィックスで追加。標準との差分を明確化し、バージョンアップ時の影響を最小化します。

C_ プレフィックス 標準 + 拡張 ER図 フィールド定義書
設計方針
従来の問題
  • カスタムフィールド名が標準と区別できず混在
  • バージョンアップで標準フィールド追加と衝突するリスク
  • 「どこが標準でどこが拡張か」がわからない設計書
C_ プレフィックスで解決
  • 全カスタムフィールドを C_ で始め、標準と即座に識別
  • IFS 標準の命名規則に準拠し、バージョンアップ衝突を防止
  • ER図・設計書でも一目で拡張箇所がわかる

C_ 拡張フィールド定義一覧
テーブルフィールド名型必須業務意味
SUPPLIER_INFO_TABC_PREFERRED_CARRIERVARCHAR2(30)—優先配送業者コード
SUPPLIER_INFO_TABC_SLA_DAYSNUMBER(3)—標準納期SLA（日数）
SUPPLIER_INFO_TABC_PAYMENT_TERMSVARCHAR2(20)—カスタム支払条件コード

PURCHASE_ORDER_TABC_APPROVAL_LEVELNUMBER(1)○必要承認レベル（1=部長/2=役員）
