仕入先マスタ 移行ジョブ定義書

バージョン 1.0　／　2026-05-26　／　IFS Cloud 25R2

1. ジョブセット概要
対象エンティティSUPPLIER_INFO_TAB（IFS Cloud 標準 + 拡張フィールド）
ジョブ数4種（抽出 / 登録 / 更新 / 削除）
実行順序EXTRACT → INSERT → UPDATE → DELETE
テスト件数抽出:5件 / 登録:5件 / 更新:3件 / 削除:2件
生成方法AI自動生成（IFS AI 基盤 / migration-job-builder スキル）
2. YAML 定義（自動出力）
# 仕入先マスタ 移行ジョブセット定義 — AI自動生成 2026-05-26 migration_job_set: name: SUPPLIER_MASTER_JOBS target_entity: SupplierHandling ifs_version: 25R2 jobs: - id: SUPPLIER_EXTRACT_ALL operation: EXTRACT filter: "objstate = 'Active'" columns: [supplier_no, name, category, preferred_carrier, sla_days] test_result: PASS # 5件抽出 - id: SUPPLIER_INSERT_BATCH operation: INSERT source: staging.supplier_import duplicate_check: true test_result: PASS # 5件登録 / 重複0件 - id: SUPPLIER_UPDATE_SLA operation: UPDATE source: staging.supplier_sla_update columns: [sla_days] filter: "objstate = 'Active'" test_result: PASS # 3件更新 - id: SUPPLIER_DELETE_INACTIVE operation: LOGICAL_DELETE source: staging.supplier_delete_list set_state: Blocked ref_check: true test_result: PASS # 2件ブロック / 参照整合性OK
3. 再実行手順
手順操作
1ステージングテーブル（staging.*）に移行元データをロード
2IFS AI 基盤で本定義YAML を migration-job-builder にインポート
3テストモード（dry-run: true）で動作確認
4確認後、dry-run: false で本番実行
5EXTRACT ジョブで件数・内容を事後検証
