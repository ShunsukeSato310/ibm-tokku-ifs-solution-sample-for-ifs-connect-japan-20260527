仕入先マスタ
基本移行ジョブ 4種

抽出・登録・更新・削除の4ジョブをAIが自動作成。テスト実行→定義出力まで全自動です。

4ジョブ自動生成 テスト済み 定義出力対応
背景
従来の課題
  • 移行ジョブの手書きに1件あたり半日かかっていた
  • SQL ミス・マッピング漏れによるテスト失敗が頻発
  • 定義書のメンテが追いつかず属人化していた
AI自動生成で解決
  • 要件入力から4ジョブを10分以内に自動生成
  • テスト実行・結果検証もAIが自律実行
  • 定義書（YAML形式）を自動出力・バージョン管理可能
ジョブ 1 — 抽出（EXTRACT）
EXTRACT SUPPLIER_EXTRACT_ALL — 全仕入先データ抽出
-- 全アクティブ仕入先を抽出 SELECT s.supplier_no, s.name, s.category, s.preferred_carrier, s.sla_days FROM supplier_info_tab s WHERE s.objstate = 'Active' ORDER BY s.supplier_no;
✓ PASS5件抽出 — IBM Japan Ltd. / Bob Components Inc. / Acme Supply Co. 含む
✓ PASS非アクティブ仕入先は除外されること
ジョブ 2 — 登録（INSERT）
INSERT SUPPLIER_INSERT_BATCH — 新規仕入先一括登録
-- ステージングテーブルから新規仕入先を一括登録 INSERT INTO supplier_info_tab (supplier_no, name, category, preferred_carrier, sla_days, rowversion) SELECT s.supplier_no, s.name, s.category, s.preferred_carrier, s.sla_days, SYSDATE FROM staging.supplier_import s WHERE s.status = 'PENDING' AND NOT EXISTS ( SELECT 1 FROM supplier_info_tab t WHERE t.supplier_no = s.supplier_no );
✓ PASS新規5件が正常登録（IBM Japan Ltd. / Bob Components Inc. 他）
✓ PASS重複チェック — 既存レコードはスキップ（0件重複）
✓ PASS必須項目（supplier_no / name）の未入力バリデーション
ジョブ 3 — 更新（UPDATE）
UPDATE SUPPLIER_UPDATE_SLA — SLA日数フィールド更新
-- SLA日数を一括更新 UPDATE supplier_info_tab s SET s.sla_days = u.sla_days, s.rowversion = SYSDATE FROM staging.supplier_sla_update u WHERE s.supplier_no = u.supplier_no AND s.objstate = 'Active';
✓ PASS3件更新 — IBM Japan Ltd.(14日→10日) / Bob Components Inc.(21日→14日) 他
✓ PASS非アクティブ仕入先は更新されないこと
ジョブ 4 — 削除（DELETE）
DELETE SUPPLIER_DELETE_INACTIVE — 非アクティブ仕入先削除
-- 論理削除: OBJSTATEをBlockedに変更（物理削除は行わない） UPDATE supplier_info_tab SET objstate = 'Blocked', rowversion = SYSDATE WHERE supplier_no IN ( SELECT supplier_no FROM staging.supplier_delete_list ) AND objstate = 'Active';
✓ PASS2件を Blocked に変更（Old-Supplier-A / Old-Supplier-B）
✓ PASS未決済の発注が残る仕入先は削除されないこと（参照整合性チェック）
